# Default 환경 — '폐쇄' 대신 '동결' 5단계

| 항목 | 내용 |
|---|---|
| 제품 | Power Platform 관리센터 · 관리형 환경 · 데이터 정책 |
| 날짜 | 2026-11 |
| 난이도 | 중 |

!!! abstract "결론"
    Default 환경은 삭제·폐쇄할 수 없으므로, **"아무것도 새로 만들거나 공유할 수 없고, 기존 자산은 자동으로 정리되는 상태"로 동결**하는 것을 목표로 합니다.

## 1. 왜 완전 폐쇄가 안 되나

- 모든 직원에게 Default 환경 메이커 권한이 자동 부여됨
- Workflow에서 만드는 Power Automate 흐름, Agent Builder로 만드는 에이전트 등은 항상 Default 환경에 생성됨
    - Agent Builder 에이전트는 UI로 확인되지는 않으나 Default의 정책을 따를 것으로 예상 (미확인)
- 일부 핵심 커넥터(Outlook 등)는 데이터 정책으로 차단할 수 없음

## 2. 동결 5단계

| 단계 | 목적 | 내용 | 운영 부담 |
|---|---|---|---|
| ① 유입 차단 | 새로 만들러 들어오는 사람 줄이기 | 개인 개발 환경 라우팅 유지, 환경 이름을 'Personal Productivity(사용 제한)' 등으로 변경, 처음 들어올 때 안내 메시지 표시 | 1회 설정 |
| ② 기능 동결 | 만들어도 외부와 연결 못 하게 | 관리형 환경 적용 후 Default 전용 데이터 정책: **모든 커넥터 차단**. 불가하면 신규 커넥터 기본값 '차단', 차단 불가 커넥터만 허용, 사용자 지정 커넥터 URL 전체 차단 | 1회 설정 |
| ③ 공유 동결 | 퍼지는 것 막기 | 앱·흐름·에이전트 공유 한도 설정, 'Everyone 공유' 계속 비활성 | 1회 설정 |
| ④ 자동 정리 | 남은 자산 줄이기 | 관리센터 '작업' 페이지로 소유자 없는 앱·장기 미사용 앱 확인 → 관리자 커넥터로 자동화. 많이 쓰는 앱은 이관 대상 목록화 → 일시 격리 → 이관 → 삭제 | 자동화 후 월 1회 확인 |
| ⑤ 예외 분리 | 어쩔 수 없이 남는 것 관리 | SharePoint 사용자 지정 폼은 별도 환경 지정, Exchange 규칙으로 Power Automate·Power Apps의 외부 메일 차단, 테넌트 격리로 다른 테넌트 연결 차단 | 1회 설정 |

## 3. 적용 전 확인할 것

- [ ] Default 환경에 관리형 환경을 켰을 때 **라이선스 영향**
- [ ] '모든 커넥터 차단'(고급 커넥터 정책) 기능이 해당 테넌트에서 사용 가능한지
- [ ] 이미 Default 환경에서 업무용으로 쓰는 앱·흐름·에이전트 목록 (이관 대상)
- [ ] Teams 안에서 생성되는 **Teams 환경은 Default와 별개로 통제** 필요

## 4. 참고: 환경 간 이관(ALM) 절충안

환경을 개발·테스트·운영 3단계로 나눌 때 모든 구간에 파이프라인을 강제하면 **파이프라인 매핑 테이블 관리 부담**이 커집니다.

- 절충안: 개발 → 테스트는 직접 이관, **테스트 → 운영 구간만 파이프라인**
- 함께 안내할 것: 개발자 환경은 일정 기간 미사용 시 자동 비활성·삭제 정책이 적용될 수 있음 (고객이 모르는 경우가 많음)
